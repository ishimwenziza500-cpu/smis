# School Management and Information System (SMIS)

SMIS is a school website and staff workspace backed by a PostgreSQL database.
The staff API requires a signed-in account; records are shared across users of
the same deployment rather than stored in browser-local demo data.

## Included modules

- Public Brightwood School information page.
- Dashboard and searchable student registration, parent/guardian, staff
  directory, school item, item collection/return, registration payment, and
  transport area records.
- Search, exact-field filters, pagination, and role-guarded create/edit/delete workflows.
- PostgreSQL constraints and linked student/item references.
- Password-based staff sign-in, expiring server-side sessions, CSRF protection,
  login throttling, and an out-of-band first-administrator workflow.
- School item/service payment records only. General school fees and
  academic-year management are intentionally not included.

The requirements provided to date ended partway through the transport
requirements. This implementation covers the visible scope and does not guess
at additional requirements.

## Requirements

- Node.js 22.9 or later.
- PostgreSQL 13 or later (managed PostgreSQL with TLS is recommended).
- The PostgreSQL command-line client (`psql`) to apply the schema.

## Configure and run locally

1. Create a PostgreSQL database and apply the schema:

   ```powershell
   $env:DATABASE_URL = "postgresql://localhost:5432/smis"
   psql "$env:DATABASE_URL" -f db/schema.sql
   ```

   Use your provider's recommended `psql` connection command if required. In
   production, require TLS for the database and set `DATABASE_SSL=true`.

2. Create a private local environment file and set its values:

   ```powershell
   Copy-Item .env.example .env
   ```

   Edit `.env` with the actual PostgreSQL connection URL. Generate a unique
   `SESSION_SECRET` (do not reuse or commit one):

   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
   ```

   Put the generated value in `.env`. Set `DATABASE_SSL=false` only for a
   trusted local PostgreSQL server. `.env` is excluded from source control.

3. Install dependencies and create the first administrator. The account
   password is prompted without echo; use a unique password of at least 12
   characters.

   ```powershell
   npm ci
   npm run create-admin -- admin@example.org "School Administrator"
   ```

4. Start the application:

   ```powershell
   npm start
   ```

   Visit `http://127.0.0.1:3000`. The same Node server serves the public page
   and staff application/API.

Additional accounts are provisioned out of band by an authorized operator:

```powershell
npm run create-user -- registrar@example.org "School Registrar" registrar
npm run create-user -- inventory@example.org "Inventory Manager" inventory
npm run create-user -- viewer@example.org "Read Only User" viewer
```

## Staff role permissions

| Role | Read | Add / edit | Delete |
|---|---|---|---|
| `admin` | All modules | All modules | All modules |
| `registrar` | Students, parents, payments | Students, parents, payments | None |
| `inventory` | Items, distributions, transport | Items, distributions, transport | None |
| `viewer` | Items and transport | None | None |

Permissions are checked by the API; hiding controls in the browser is not the
security boundary. Administrators provision staff accounts using the private
CLI. Staff directory records are separate from sign-in accounts.

## Online deployment

The included [Render Blueprint](./render.yaml) configures a paid persistent
web service and managed PostgreSQL database in the same region. The database
has a private-only IP allowlist, the session secret is generated by Render,
the schema is applied before each deploy, and Render checks `/api/health`.
These paid Render service/database plans incur monthly charges; review current
pricing and select your account/region before creating the Blueprint.

1. Put this project in a GitHub or GitLab repository and push the branch
   containing `render.yaml`.
2. In Render, choose **New → Blueprint**, connect the repository, and create
   the `render.yaml` Blueprint. Review the service and PostgreSQL plan/cost
   before confirming. Keep the generated `SESSION_SECRET` private.
3. Wait for the service's first deployment to complete and verify the health
   check reports a connected database.
4. From Render's authorized Shell for the `smis` web service, create the first
   administrator using:

   ```sh
   npm run create-admin -- admin@example.org "School Administrator"
   ```

   Enter the unique password at the hidden prompt. Do not put credentials in
   source control or in command arguments.
5. Visit the service's HTTPS `onrender.com` URL and sign in. Provision other
   staff accounts using `npm run create-user` from the authorized service
   shell.

Blueprints require a connected Git repository and an authorized Render account.
Those external accounts aren't available from this project folder, so the
steps above still require an operator to create the hosted resources. Leave
`CORS_ORIGIN` unset: this deployment serves the website and API from one HTTPS
origin. See [Render deployment notes](./docs/render-deployment.md) for rollout,
verification, and operations details.

## Data and security notes

- The backend enforces validated fields, parameterized values, constrained SQL
  identifiers, linked record integrity, hashed session tokens,
  `HttpOnly`/`SameSite=Strict` cookies, CSRF checks for logout and data changes, security
  headers, and per-process sign-in rate limits.
- Passwords use Node scrypt; sessions expire after 12 hours.
- In-memory rate limiting is per application process. Use a trusted edge rate
  limiter when deploying multiple replicas.
- This initial implementation is not a substitute for a school-specific
  privacy/compliance review. Secure hosting and database access, restrict
  operational permissions, configure tested backups/retention, and never
  commit credentials.
- The interface currently formats amounts as USD. Confirm school currency,
  policies, consent/retention needs, and the rest of the requirements before
  production use.
